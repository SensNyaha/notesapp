# Tasks — этап 01, версия 0.1.1

Первый проверяемый этап совместной разработки PWA для заметок и напоминаний.

Реализовано:

- Preact, интерфейс проверки первого запуска.
- Fastify: API и раздача только заранее известных публичных файлов с одного порта 3100.
- Встроенный `node:sqlite`, SQLite WAL, первая миграция схемы.
- Постоянный идентификатор установки и счётчик запусков сервера.
- PWA manifest, иконки, Service Worker с офлайн-кешем только публичной оболочки.
- Обновление оболочки через кнопку, когда новая версия готова.
- Docker Compose с постоянным томом, healthcheck и ограничением размера логов.

В этом этапе ещё нет аккаунтов, заметок, шифрования записей, IndexedDB, расписания и push. Web Crypto на странице — проверка доступности браузерного API, а не реализованное шифрование. Офлайн работает оболочка приложения, а не заметки. Сервер не принимает пользовательское содержимое.

## Запуск без Docker

Понадобится Node.js 24.x и npm. Docker предпочтительнее: он даёт одинаковую версию Node.js и окружение на разных компьютерах.

```bash
npm ci
npm run build
npm start
```

Открыть http://localhost:3100. По умолчанию сервер слушает 127.0.0.1, SQLite находится в `./data/tasks.sqlite`. После правок клиента повторить `npm run build`; после правок сервера перезапустить `npm start`.

```bash
npm run check
```

Тесты запускаются после сборки. Они проверяют API, сохранение идентификатора при повторном открытии SQLite, недоступность исходников через HTTP, исключение API из кеширования и офлайн-оболочку в модели Service Worker. Это не браузерные тесты.

| `docs/ARCHITECTURE.md`     | Архитектура и границы этапа                                         |
| `docs/DECISIONS.md`        | Принятые решения и следующие этапы                                  |

Клиент и сервер пока используют стандартные ES-модули JavaScript, чтобы первый этап собирался только средствами Node.js, без отдельного bundler. Preact копируется из зафиксированной npm-зависимости. Перед появлением основной предметной логики подключим TypeScript и Vite, чтобы общие типы API и криптографических конвертов проверялись на этапе сборки.

Версии npm-зависимостей зафиксированы в `package.json` и `package-lock.json`; используйте `npm ci`. Образ Node.js закреплён на ветке 24 LTS Debian Bookworm, но тег получает исправления. Простая работа с SQLite изолирована в `server/db.mjs`, поэтому возможное изменение API `node:sqlite` не затронет формат БД. Перед хранением реальных данных ещё раз оценим зрелость этого API и зафиксируем точный образ. Для точного отката сохраняйте предыдущий образ перед следующими этапами.
